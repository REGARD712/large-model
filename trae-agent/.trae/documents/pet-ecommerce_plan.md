# 宠物电商网站实施计划

## 仓库研究结论

当前仓库是一个**单页咖啡网站**（慢时光咖啡），包含 3 个文件：

* `index.html` — 单页静态 HTML，含导航、轮播、菜单、联系表单等

* `style.css` — 咖啡棕色调的响应式样式，已有温暖色调、卡片网格、轮播、滚动导航等可复用模式

* `script.js` — 菜单数据、轮播、汉堡菜单、滚动高亮等交互逻辑

**关键发现**：

1. 现有 CSS 的\*\*暖色调（棕/奶咖/米白）\*\*可直接复用或调整为更适合宠物的暖橘/暖粉色调
2. **响应式卡片网格、轮播、汉堡菜单、导航栏滚动效果**等 UI 模式可直接复用
3. 现有 JS 中的**数据渲染模式**（数据 + 模板字符串生成 DOM）可用于产品列表渲染
4. 但整个项目需要**完全重写**，不是扩展——这是一个完整的电商系统

## 架构决策

### SPA 架构（单页应用）

由于仅限 HTML/CSS/JS，无后端，采用 **Hash Router SPA** 方案：

* 一个 `index.html` 承载所有页面视图

* 通过 JS 监听 URL hash 变化（如 `#/`, `#/login`, `#/cart`）切换视图内容

* 页面间状态（购物车、登录状态、地址、订单）通过 **localStorage** 持久化

### 数据模型（localStorage）

```javascript
// 产品目录（内存中，不存 localStorage）
products: [{ id, name, category, price, originalPrice, images[], size, description, reviews[] }]

// 用户注册/登录
users: [{ phone, password, nickname, avatar }]  // localStorage
currentUser: { phone, nickname, avatar } | null   // localStorage

// 购物车
cart: [{ productId, quantity, selectedSize }]   // localStorage

// 收货地址
addresses: [{ id, name, phone, province, city, detail, isDefault }]  // localStorage

// 订单
orders: [{ id, items[], total, address, paymentMethod, status, createTime }]  // localStorage
```

### 页面/视图清单

| Hash 路由              | 视图    | 说明                         |
| -------------------- | ----- | -------------------------- |
| `#/`                 | 首页    | 轮播图、宠物分类入口、推荐宠物、热销排行、新用户弹窗 |
| `#/category/:cat`    | 商品列表页 | 分类筛选、排序、卡片网格               |
| `#/product/:id`      | 商品详情页 | 图片轮播、尺寸选择、加入购物车、评价展示       |
| `#/login`            | 注册登录页 | 手机号登录/注册、微信登录（模拟）          |
| `#/cart`             | 购物车页  | 商品列表、数量调整、删除、结算入口          |
| `#/checkout`         | 结算页   | 地址选择/新建、商品确认、提交订单          |
| `#/payment/:orderId` | 支付页   | 支付宝/微信支付/银行卡（模拟）           |
| `#/orders`           | 历史订单页 | 订单列表、状态筛选                  |
| `#/contact`          | 联系我们  | 邮件表单（mailto 跳转）            |

### 共享布局

* **顶部导航栏**：Logo、分类导航、搜索框、购物车图标（带数量角标）、用户头像/登录按钮

* **底部栏**：关于、帮助、联系方式、版权

* **全局消息提示 Toast**

## 视觉风格

* **主色调**：温暖橘粉 `#FF8A5B`（类似 `#FF9A76`），辅助奶油色 `#FFF5F0`、暖棕 `#8B4513`

* **背景**：奶油白 `#FFFAF7`

* **强调色**：腮红粉 `#FFB6A3`、金色 `#D4A574`

* **大图展示**：产品卡片使用大比例图片（3:4 或 1:1）

* **圆角**：卡片 16px，按钮 24px（胶囊形）

* **动效**：卡片悬浮上移、轮播淡入、弹窗缩放、按钮涟漪

## 文件结构

```
trae-agent/
├── index.html        # SPA 入口，包含所有视图模板占位
├── style.css         # 全部样式（重写，暖色调）
└── script.js         # 全部逻辑（重写，路由+数据+交互）
```

## 实施步骤（按依赖顺序）

### 第一阶段：基础框架

1. **重写** **`index.html`** — SPA 入口结构

   * 顶部导航栏（固定、带搜索、购物车图标、登录/用户菜单）

   * 主内容容器 `<main id="app-view">`（JS 动态渲染内容）

   * 底部栏

   * 全局弹窗容器（新用户弹窗、Toast、模态框）

   * 全局 SVG 图标内联（购物车、搜索、微信、支付宝等）

2. **重写** **`style.css`** — 暖色主题样式框架

   * CSS 变量（新暖色调色板、间距、圆角、阴影）

   * 全局重置、排版

   * 导航栏、底部栏样式

   * 通用组件：按钮（主要/次要/禁用）、卡片、徽章、Toast、模态框

   * 响应式断点：1200px / 768px / 480px

3. **搭建** **`script.js`** **核心基础设施**

   * Hash Router：监听 `hashchange`，映射路由到渲染函数

   * 工具函数：`$()`、`$$()`、模板字符串渲染、showToast、showModal

   * 数据层：localStorage 读写封装（`getCart()`、`saveCart()`、`getUser()` 等）

   * 产品目录 Mock 数据（15-20 只宠物，含猫/狗/兔/仓鼠分类）

### 第二阶段：商品浏览流程

1. **实现首页** **`renderHome()`**

   * 大图轮播（复用现有轮播逻辑，改为宠物图）

   * 分类入口网格（猫、狗、小宠、水族等图标+文字）

   * 推荐宠物横滑卡片（带"查看更多"链接）

   * 热销宠物网格（带销量徽章）

   * 新用户注册弹窗（首次访问或未登录时弹出，5秒后可关闭）

2. **实现商品列表页** **`renderCategory(category)`**

   * 分类筛选 Tab（猫/狗/小宠/全部）

   * 排序按钮（价格升/降、热销、最新）

   * 产品卡片网格（图片、名称、价格、销量标签）

   * 空状态提示

3. **实现商品详情页** **`renderProduct(id)`**

   * 顶部面包屑返回

   * 左侧大图 + 缩略图切换（简单切换，不做复杂轮播）

   * 右侧信息：名称、价格、原价划线、销量、尺寸选择（下拉或按钮组）

   * 描述段落 + 大图展示

   * 用户评价列表（头像、昵称、星级、评论、日期）

   * 底部悬浮"加入购物车"和"立即购买"按钮（移动端友好）

### 第三阶段：用户系统

1. **实现登录/注册页** **`renderLogin()`**

   * Tab 切换：登录 / 注册

   * 手机号输入 + 验证码（模拟：点击后显示 123456）

   * 密码输入（注册时需二次确认）

   * 微信登录按钮（模拟：点击后延迟 1 秒自动登录）

   * 表单校验 + 错误提示

   * 登录成功后 Toast 提示 + 跳转首页

2. **更新导航栏用户状态**

   * 未登录：显示登录按钮

   * 已登录：显示头像 + 昵称下拉菜单（我的订单、我的地址、退出登录）

   * 购物车角标实时更新（数量变化时刷新）

### 第四阶段：购物流程

1. **实现购物车页** **`renderCart()`**

   * 空购物车状态（引导去逛逛）

   * 商品列表：缩略图、名称、尺寸、单价、数量调节器（±按钮）、小计、删除

   * 全选复选框（联动底部结算区）

   * 底部悬浮结算栏：已选数量、合计金额、去结算按钮

   * 数量为 0 时自动移除商品

2. **实现结算页** **`renderCheckout()`**

   * 收货地址卡片：默认地址 + "更换/新增地址"按钮 + 地址选择弹窗

   * 商品清单（不可编辑，仅展示）

   * 订单金额明细（商品总额、运费、合计）

   * 提交订单按钮 → 创建订单 → 跳转支付页

3. **实现地址管理（结算页内）**

   * 新建地址表单：姓名、手机、省市区（下拉模拟）、详细地址、设为默认

   * 地址列表选择（单选，点击即切换）

   * 编辑/删除地址

4. **实现支付页** **`renderPayment(orderId)`**

   * 订单金额大标题

   * 支付方式选择（3 个卡片，带图标）：

     * 微信支付（绿色 #07C160 图标）

     * 支付宝（蓝色 #1677FF 图标）

     * 银行卡（默认卡片图标）

   * 点击后显示确认弹窗

   * 模拟支付过程（2 秒进度动画）→ 成功页面

   * 支付成功 → Toast + 跳转订单详情或订单列表

### 第五阶段：订单与联系

1. **实现历史订单页** **`renderOrders()`**

   * Tab 筛选：全部 / 待支付 / 已支付 / 已完成 / 已取消

   * 订单卡片：订单号、商品缩略图、商品名、合计、状态标签、创建时间

   * 每个订单操作按钮（根据状态不同：去支付 / 查看详情 / 确认收货）

2. **实现联系我们页** **`renderContact()`**

   * 客服邮箱大展示

   * 邮件链接（`mailto:` 协议跳转系统邮件客户端）

   * 或内嵌表单 → 提交后复制邮箱到剪贴板 + Toast 提示

### 第六阶段：打磨与验证

1. **交互动效完善**

   * 购物车数量变化时导航栏数字动画

   * 页面切换过渡（淡入效果）

   * 按钮点击涟漪效果

   * 图片加载占位（Skeleton 或背景色）

2. **全流程验证**

   * 移动端（480px）、平板（768px）、桌面（1200px）三档检查

   * 完整下单流程走通：浏览→加购→结算→支付→查订单

   * localStorage 跨刷新保持状态

   * 空状态、错误状态边界测试

## 依赖与注意事项

### 外部资源

* **宠物图片**：使用 `https://trae-api-cn.mchost.guru/api/ide/v1/tool_text_to_image` 生成，prompt 用 "cute \[cat/dog/rabbit/hamster] photo, professional pet photography, white background"，尺寸用 `square_hd` 或 `landscape_4_3`

* **图标**：使用内联 SVG（自绘简单图标），或使用 emoji fallback（🛒 🔍 🐱 🐶 等）

* **字体**：系统中文字体 PingFang SC / Microsoft YaHei，无需外部加载

### 关键假设

* 无真实后端，所有用户数据、订单、地址、购物车均存 localStorage

* 支付、微信登录均为**模拟流程**，UI 接近真实但不连接真实服务

* "验证码"固定为 123456，仅前端校验

* 商品图片使用 placeholder 图片服务或 tool\_text\_to\_image API 生成

### 可复用的现有代码

| 现有元素        | 复用方式                         |
| ----------- | ---------------------------- |
| 轮播实现        | 直接复用 JS 逻辑，改 CSS 类名即可        |
| 汉堡菜单        | 移动端导航复用                      |
| 响应式断点       | 直接复用或微调                      |
| 卡片 hover 动效 | 复用 translateY(-8px) + shadow |
| 导航栏滚动效果     | 复用 scrolled class 切换         |
| CSS 变量结构    | 换色值但保留变量架构                   |

## 验证方式

* 本地打开 `index.html`（或用 Python/Node 起一个静态服务器）

* 手动走查所有用户流程（浏览 → 注册 → 加购 → 结算 → 支付 → 查订单）

* 浏览器 DevTools 切换设备模拟，检查移动端布局

* 清空 localStorage 测试首次访问的新用户弹窗

## 风险与应对

| 风险                                    | 应对                                            |
| ------------------------------------- | --------------------------------------------- |
| 无真实后端，刷新或换浏览器数据丢失                     | 在 UI 上注明"为演示环境，数据保存在本地浏览器"                    |
| tool\_text\_to\_image 生成图片可能有延迟       | 提前生成所有图片 URL，或使用 picsum.photos 作为 fallback    |
| 路由 SPA 在浏览器直接打开 file:// 可能有 hash 兼容问题 | 建议用简单 HTTP server（`python -m http.server`）预览  |
| 微信/支付宝图标版权                            | 使用通用 SVG 图标或 emoji，模拟 UI 不使用真实品牌 logo         |
| localStorage 容量限制（\~5MB）              | Mock 数据量不大，产品目录存在内存中，仅用户/订单/购物车存 localStorage |
